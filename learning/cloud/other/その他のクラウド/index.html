基礎LESSON 16

この教材で学ぶこと Cloudflareとニフクラを学び、用途・責任・費用から選定します。

Cloudflare・ニフクラとその他のクラウド

前提: 三社の比較。クラウドを用途から選ぶ練習をする。

1. この章で広げる視点

クラウドには総合的な基盤に加え、配信や保護、アプリ実行、国内のインフラ運用などから検討するサービスがある。 「一社ですべて構成する」と「得意な機能を組み合わせる」の両方を、責任分界と運用から比較する。 ここではCloudflareを配信・保護・エッジ実行の入口から、ニフクラをIaaSの構築・運用の入口から学ぶ。

2. Cloudflare — DNS・配信・保護から理解する

DNSは名前解決、CDNはコンテンツ配信、WAFはWebリクエストの検査と制御を担う。 この三つの役割を分けてから、Cloudflareをポータルの前段に置く構成を考える。 DNSで名前を管理するだけの場合と、HTTP通信をプロキシさせる場合では、通信経路と適用される機能が異なる。

利用者 → Cloudflareの配信・保護 → オリジン側の入口 → アプリ → DB
                  └→ キャッシュ対象のコンテンツ

WAFを経由しないオリジンへの直接アクセスが残ると、前段で検査する前提が崩れる。 オリジンへの接続制限、TLSの検証、元の接続元情報、ログの照合を設計する。 「Cloudflareに追加した」だけで保護が完成したとは判断しない。

利用者限定教材はキャッシュと認証が重要。 未認証の利用者にキャッシュが返らないか、利用者ごとの応答が共有されないか、権限失効後にどう扱うかを確認する。 運用者向けアプリを保護する場合はCloudflare Accessなども検討するが、アプリ内部の認可まで自動で代替されるとは考えない。

公式の入口: Cloudflare学習リソース

3. WorkersとR2 — アプリの実行・保存

WorkersはCloudflareのネットワーク上でアプリを実行するための基盤。 API、入口での軽い処理、外部サービスとの連携などを題材にし、実行モデル・API・制限・データの配置を確認する。 既存VM上の常駐アプリを変更せず動かす前提では選ばない。Workers公式資料

R2はオブジェクトストレージで、S3互換APIを提供する。 ただしS3の全機能が同一という意味ではない。既存アプリが使う操作を互換表と照合する。R2の概要、S3 API互換性

演習: 教材PDFをR2に置き、Workersが認証済みの要求だけを扱う案を書く。 確認項目はユーザー認証、教材への認可、非公開バケット、期限付きアクセスの扱い、監査、費用。 解答例: 認証できたことに加え、その利用者が対象教材を読めることを判定する。 バケットを直接公開するとこの判定を迂回し得るので、アクセス経路を限定して試験する。

4. ニフクラ — IaaSを運用まで学ぶ

ニフクラではサーバー、ネットワーク、ファイアウォール、ロードバランサーなどの構成要素を、公式の機能一覧と仕様から確認する。 共通基礎で学んだ通信図を描き、AWS固有の用語をそのまま設定名として使わない。 提供される機能はニフクラドキュメントを起点に、ネットワーク仕様などで確認する。

最初の学習対象は次の六つ。

対象 自分で説明すること
サーバー OS、スペック、ディスク、配置、更新と再作成
ネットワーク パブリック／プライベートの接続、IP、ルーティング
通信制御 利用者→入口、入口→アプリ、アプリ→DBの許可条件
負荷分散 ヘルスチェック、障害時の振分け、TLS終端
データ保護 利用可能な保存・バックアップ機能、保持、復元
運用 監視、問い合わせ経路、保守、契約・費用、障害時の担当

学習用の比較案として、Web/アプリ用サーバーとDB用サーバーを分けるIaaS構成を考える。 自分でDBを運用する案では、OSだけでなくDB更新、複製、バックアップ、復旧まで担当範囲に入れる。 マネージド機能を使う案と比べるときは、対象リージョンや対応エンジンを現行仕様で確認する。

国内サービスだから要件を自動的に満たすと考えず、データの保存先、サポート範囲、接続、SLA、契約を確認する。 閉域接続が必要なら、経路・帯域・冗長化・申込や運用の分担を設計し、サービス提供者への確認事項を残す。

演習: ニフクラ上のIaaS構成でポータルを運用するときの担当表を書く。 解答例: 利用者側がOS・アプリ・自前DBの更新と復旧を担当する部分を明記し、基盤障害時の連絡・復旧範囲は契約で確認する。 マネージドDBとの比較では、VM料金に加えて更新・監視・復元訓練の工数を費用へ含める。

5. その他のクラウドを調べる順序

次はOCI、さくらのクラウド、IBM Cloud、Alibaba Cloudなどから、実際の用途に合う一社を選んで深める。 今回の必修本文はCloudflareとニフクラまで。他社は以下の調査票を使う選択学習とする。 ブランドの印象だけで強みを断定せず、同じポータルの要件で比較する。

調査項目 記録する内容
要件 地域、既存システム、ID連携、サポート、予算
機能 実行、保存、ネットワーク、権限、監視の候補
責任 利用者が更新・バックアップ・復旧する範囲
互換性 アプリAPI、データ形式、DB、IaCの移植差分
費用 同じ利用量での見積、転送、サポート、運用工数
根拠 公式URL、確認日、提供条件、未確認事項

6. 最終演習と理解度チェック

「AWSだけで構成」「AWSなどの前段にCloudflare」「ニフクラのIaaSで構成」の三案を比較する。 すべてを実際に構築する必要はない。構成図、責任分界、障害時の連絡先、費用の項目を揃えて評価する。

解答例: 前段にCloudflareを追加する案は配信・保護の機能を評価できるが、TLS、キャッシュ、オリジン制限、二社の障害切り分けを追加で設計する。 ニフクラのIaaS案は既存アプリの要件と照合し、自分で運用するOS・DBの責任を見積もる。 単一クラウド案は管理対象をまとめやすいが、必要機能や契約条件を満たすか確認する。

問い 解答の要点
CloudflareはDNSだけのサービスか 配信・保護・実行・保存なども学習対象になる
R2ならS3の機能を全部使えるか 互換APIの対応範囲を確認する必要がある
WAFを置けばオリジンの公開制御は不要か 不要にはならない。迂回経路を確認する
IaaSで自前DBを動かすと何を引き受けるか DBとOSの更新、バックアップ、監視、復旧など
新しいクラウドの調査は何から始めるか 解決する要件と、根拠を残す比較項目から始める
