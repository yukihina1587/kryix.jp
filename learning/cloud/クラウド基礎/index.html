はじめてLESSON 01

この教材で学ぶこと compute、storage、network、database、identityを役割から学びます。

クラウド基礎

対象読者: AWS、Google Cloud、Cloudflareなどを学ぶ前に、cloud computingの判断軸を知りたい人。

この教材でできるようになること

  • on-premisesとcloudの違いを所有・責任・課金から説明できる
  • compute、storage、network、database、identityを分類できる
  • availability、security、cost、operationのtrade-offを整理できる
  • 小さなsystemを要件から構成へ落とせる

1. cloudは「他人のPC」だけではない

cloud providerは、計算、保存、network、identity、監視などをAPI経由で組み合わせられる形で提供します。価値はserverの場所だけでなく、必要時に作成・変更でき、使用量を観測し、自動化できることにあります。

2. 基本serviceを五つに分ける

分類 問うこと 例
compute codeをどこで実行するか VM、container、function
storage fileをどう保存するか object、block、file storage
network どこからどこへ通信できるか VPC、subnet、load balancer、CDN
database dataをどう検索・更新するか relational、key-value、cache
identity 誰が何をできるか user、role、policy

製品名を暗記する前に、この問いへ戻ります。

3. shared responsibility

providerがすべてを守るわけではありません。managed serviceの範囲が広いほどOS patch等をproviderへ任せられる一方、data、identity、application code、設定は利用者側に残ります。

責任境界はserviceごとに異なるため、公式documentで確認します。

4. availabilityを設計する

利用者
  ↓
DNS / CDN
  ↓
Load Balancer
  ↓
Application (複数failure domain)
  ↓
Database + backup

部品を増やせば自動的に高可用になるわけではありません。health check、timeout、retry、data整合性、復旧手順、監視を一緒に考えます。

5. costを四つに分ける

  • 常時稼働する固定的なresource
  • requestや実行時間に比例するresource
  • 保存容量とoperation回数
  • data transfer

小規模ではserverlessが安くても、負荷や待ち時間、運用要件によって答えは変わります。見積り後もbudget alertと実績を確認します。

6. 最小権限から始める

  • 人のaccountとworkload identityを分ける
  • 長期credentialをcodeへ埋め込まない
  • roleと一時credentialを優先する
  • resourceとactionを必要範囲へ絞る
  • audit logを有効にし、変更を追えるようにする

演習: 静的サイトを設計する

次の要件を満たす構成を考えてください。

  • HTML/CSS/画像だけ
  • 世界中から閲覧
  • 更新は週一回
  • server管理は避けたい
  • 月額上限を決めたい
  • 独自domainとHTTPSが必要

computeが必要か、object storageまたはstatic hosting、CDN、DNS、certificate、deploy、rollbackをどうするかを書きます。

理解チェック

  • serviceを製品名ではなく役割で分類できる
  • providerと利用者の責任を区別できる
  • availabilityと複雑性のtrade-offを説明できる
  • costの主要因と上限管理を説明できる
